# SQL

Учебный репозиторий, содержащий комплексные скрипты на языке Transact-SQL (T-SQL) для СУБД Microsoft SQL Server. Внутри реализованы структуры хранения данных электронного расписания, учета успеваемости, а также серверные процедуры и функции для автоматизации логики учебного процесса.

---

## Реализация теории баз данных и T-SQL

Скрипты спроектированы на основе правил реляционных СУБД:
* **Реляционная модель:** Данные разбиты на независимые сущности (таблицы), состоящие из полей и записей.
* **Нормализация и связи между таблицами:** Исключена избыточность данных. Связи один-ко-многим (`One-to-Many`) настроены через внешние ключи `FOREIGN KEY REFERENCES`. Связи многие-ко-многим (`Many-to-Many`) приведены к нормальному виду через промежуточные связующие таблицы отношений с составными первичными ключами: `TeacherDisciplinesRelation` и `DisciplinesDirectionsRelation`.
* **Типизация данных MS SQL Server:**
  * Числовые: точные (`TINYINT` для ID направлений и оценок, `SMALLINT` для ID дисциплин, `INT` для ID студентов и групп, `BIGINT IDENTITY(1, 1)` для уникальных ID уроков в расписании).
  * Финансовые и временные: `MONEY` для тарифных ставок преподавателей, `DATE` для дней рождений, `TIME(0)` для фиксации времени начала пар с точностью до секунды.
  * Бинарные и строковые: `VARBINARY(MAX)` под хранение файлов фотографий, `NVARCHAR` (в Юникоде) разной длины для текстовых ФИО, названий предметов и тем домашних заданий.
* **Ограничения целостности (Constraints):** Для контроля корректности ввода оценок успеваемости и экзаменов добавлены жесткие ограничения диапазона `CHECK` от 1 до 12 баллов (`grade >= 1 AND grade <= 12`).

## Разбор структуры и скриптов

### 1. Проектирование таблиц (ALL_IN_ONE/SQLQuery1.sql)
Скрипт развертывания структуры базы данных академии. Поочередно создает связанные таблицы:
* `Directions` и `Groups` — направления обучения и учебные группы.
* `Teachers` и `Disciplines` — анкеты преподавателей и перечень предметов.
* `Students` — анкеты учащихся со ссылкой на группу.
* `Schedule` — журнал расписания занятий с флагом проведения урока `spent` (`BIT`).
* `Grades`, `Exams`, `Homeworks` и `HWresults` — таблицы фиксации текущих оценок за пары, экзаменационных ведомостей, условий и результатов выполнения домашних работ.

### 2. Выборка, модификация и агрегация (DML)
* **`SQLQuery1-INSERT.sql`:** Демонстрирует первичное наполнение справочников строками через множественную вставку `INSERT INTO ... VALUES`.
* **`SQLQuery1-SELECT.sql`:** Извлекает данные студентов. ФИО склеивается в одну строку встроенной функцией `FORMATMESSAGE`. Возраст рассчитывается динамически в часах через разницу между датой рождения и текущим временем `GETDATE()`, деленную на среднее количество часов в году (`8766`).
* **`SQLQuery2-AGREGATION.sql`:** Группирует данные через оператор `GROUP BY` с подсчетом количества строк функцией `COUNT()`. Реализует подзапросы со сравнением результатов агрегации, отсекая пустые группы с нулевым числом учащихся.

### 3. Календарные и вспомогательные функции (Functions)
Блок кастомных скалярных функций для автоматизации учебного календаря с предварительной жесткой установкой первого дня недели — понедельника (`SET DATEFIRST 1`).

* **`GetEasterDate.sql`:** Реализует математический алгоритм расчета даты Пасхи для заданного года с использованием остатков от деления `%` и возвратом значения через тернарное условие `IIF`.
* **`GetSummerHolidaysStartDate.sql`:** Вычисляет дату начала летних каникул на основе смещения от первого августа к первому понедельнику месяца функцией `DATEPART(WEEKDAY, ...)`.
* **`GetNewYearHolidaysStartDate.sql`:** Рассчитывает дату старта новогодних каникул от первого января. Содержит логическое ветвление `IF / ELSE`, сдвигающее старт на два дня назад, если первое января выпадает на пятницу, субботу или воскресенье.
* **`GetHolidaysStartDate.sql`:** Обобщающая функция-хаб. Через конструкцию многопоточного выбора `CASE WHEN ... LIKE` проверяет текстовое название праздника и перенаправляет вызов на специфичные функции (`dbo.GetEasterDate`, `dbo.GetNewYearHolidaysStartDate`) или забирает фиксированные числа из таблицы `Holidays`.
* **`SQLQuery1.sql` (GetTeacherID):** Компактная функция для быстрого получения идентификатора преподавателя (`SMALLINT`). Принимает строковое значение `@name` и ищет совпадение по имени или фамилии внутри таблицы `Teachers`.

### 4. Хранимые процедуры (StoredProcedures)
Серверные процедуры для автоматизации заполнения таблиц и генерации расписания циклической обработкой данных.

* **Автоматизация праздничных дней:**
  * `sp_InsertDayOFF` — добавляет запись в таблицу `DaysOFF`, увеличивает счетчик дней и сдвигает дату на один день вперед через `DATEADD`.
  * `sp_SetDaysOFF` — находит длительность и стартовую дату через функцию `dbo.GetHolidaysStartDate`, после чего запускает цикл `WHILE` и вызывает внутри него `sp_InsertDayOFF`.
  * `sp_SetAllHolidaysFor` — процедура-диспетчер. Одной командой генерирует полный календарь выходных дней на указанный год, последовательно вызывая `sp_SetDaysOFF` для Нового года, 23 февраля, 8 марта, Пасхи, Майских и Летних каникул.
* **Генерация расписания занятий:**
  * `sp_InsertLesson` — проверяет отсутствие дубликатов на указанную дату и время. Если пары нет, добавляет занятие в таблицу `Schedule`. Флаг `spent` вычисляется на лету через `IIF` (1, если дата уже прошла, и 0, если пара планируется в будущем). После вставки сдвигает время начала следующего урока вперед на 95 минут (длительность пары).
  * `sp_InsertSchedule` — автоматический генератор полного цикла лекций по предмету. Принимает имя группы, дисциплину, имя преподавателя, дату старта и время первой пары. Внутри цикла `WHILE` процедура генерирует по две пары за один учебный день, сдвигая дату на следующий учебный день группы с помощью внешней календарной функции `dbo.GetNextLearningDate`.
  * `sp_SelectSchedule` — форматированный вывод расписания на экран через связывание таблиц в секции `WHERE`.

### 5. Скрипты отладки и проверки (Transact-SQL)
* **`SQLQuery2-INSERT Schedule.sql` (Прямой скрипт генерации):** Автономный отладочный скрипт, дублирующий логику генератора расписания. Рассчитывает максимальный текущий `lesson_id` в таблице (`ISNULL(..., 0) + 1`), запускает цикл по лимиту лекций дисциплины и автоматически рассчитывает шаг дней. Если текущий день недели — вторник (2), следующий день сдвигается на 2 дня вперед (четверг), иначе — на 5 дней вперед (следующий вторник).
* **`SQLQuery1-SELECT Schedule.sql` (Выборка через подзапросы):** 
  Отладочный скрипт для вывода расписания на экран, демонстрирующий альтернативный способ объединения данных без использования классических операторов `JOIN`:
  * Связывание с таблицами `Groups` и `Disciplines` происходит через **вложенные скалярные подзапросы `SELECT`** в блоке полей, где ID группы и предмета из таблицы `Schedule` сопоставляются со справочниками.
  * Полное ФИО преподавателя склеивается с помощью оператора конкатенации строк `+` прямо внутри вложенного подзапроса к таблице `Teachers`.
  * Текстовый день недели вычисляется функцией `DATENAME(WEEKDAY, [date])`.
  * Логическое поле флага проведения пары `spent` переводится в понятный человеку статус (*Провелено / Запланировано*) с помощью условной конструкции `CASE WHEN spent = 1 THEN ... ELSE ... END`.
  * Результаты выборки жестко сортируются по хронологии с помощью `ORDER BY [date], [time]`.
* **`SQLQuery0-CHECK PROCEDURES.sql`:** Служебный файл для ручного тестирования и запуска процедур.

## Работа с проектом в SSMS

1. Откройте Microsoft SQL Server Management Studio и подключитесь к экземпляру SQL Server.
2. Для развертывания структуры создайте целевую базу данных и выполните скрипт `ALL_IN_ONE/SQLQuery1.sql`.
3. Скомпилируйте все заготовки функций из папки `Functions` и процедуры из папки `StoredProcedures`.
4. Для генерации сетки занятий и проверки выборки через подзапросы выполните команды:
   ```sql
   EXECUTE sp_InsertSchedule N'P_421', N'%MS SQL Server', N'Олег', N'2026-03-26', N'14:00';
   
   -- Запуск отладочного скрипта выборки
   SELECT lesson_id AS N'ID', 
          (SELECT group_name FROM Groups WHERE group_id = [group]) AS N'Группа',
          [date] AS N'Дата'
   FROM Schedule;
   ```
